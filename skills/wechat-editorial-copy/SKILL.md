# wechat-editorial-copy

## 目标

把已经完成内容审核的 Markdown 长文，转换成：

`Markdown → 人物式编辑排版 → 全内联 HTML → 一键复制富文本 → 微信公众号编辑器粘贴`

用户最终操作只应是：

1. 打开生成的 HTML；
2. 点击「复制正文（富文本）」；
3. 微信公众号后台新建图文；
4. 标题栏单独填标题；
5. 正文 Ctrl/Cmd+V；
6. 手机预览，必要时微调图片；
7. 用户自己保存/发布。

**默认不调用公众号 API，不尝试自动 push 草稿箱。**

---

## 一、内容边界

### 可以做

- 合并过碎的短段落，但不改字句和论证顺序；
- 把标题、重点句、图注、参考资料改成统一编辑格式；
- 删除明确的公众号宣传尾巴，例如「星标」「点赞」「在看」「关注我们」「往期推荐」；
- 把本地/相对图片改成公开 HTTPS 地址；
- 生成可复制的全内联富文本 HTML；
- 对复制后的微信兼容性做静态检查。

### 不可以做

- 不改核心观点；
- 不改事实和数据；
- 不为了排版自行补写新结论；
- 不删除正文论证；
- 不把文章做成 PPT / 知识卡片 / 小红书长图；
- 不重新加入公众号 API 发布逻辑。

---

## 二、人物式长文的版式结构

以下规则来自用户提供的《人物》完整文章与实页截图，属于本 skill 的默认结构。

### 1. 开头：首图 + 灰色引言框

如果稿件有 hero/cover 图，可在正文最前放一张全宽首图；没有则直接进入引言框。

引言框：

- 背景：#f3f3f3 ~ #f5f5f5；
- 不加边框；
- 内边距约 24–28px；
- 16px 正文；
- 行高约 1.9；
- 可以放 1–2 个完整段落；
- 不把每句话拆成单独一行；
- 引言结束后保留较大的纵向留白。

优先把 Markdown 正文最前的 blockquote 当作 lead；如果没有 blockquote，则允许把开头 1–2 个摘要段落放进 lead。

### 2. 可选作者 / 编辑信息

如果 frontmatter 有 `author` / `editor`：

- 放在引言框之后；
- 右对齐；
- 14px 左右；
- 标签「文｜」「编辑｜」加粗；
- 上下保留明显空白。

没有元数据就完全省略，不要猜作者。

### 3. 正文小标题

《人物》式标题不是彩色色块，而是正文中一个略大的黑体节点。

默认：

- 18px；
- 700；
- 左对齐；
- 上方留白 3.2–3.8em；
- 下方留白 1.6–2em；
- 自动用中文直角引号包起来：`「标题」`；
- 不使用蓝色竖线、编号卡片、渐变、emoji。

如果原标题已经有「」则不重复添加。

### 4. 正文段落

正文默认：

- 16px；
- line-height 1.8–1.9；
- letter-spacing 0.02–0.04em；
- text-align: justify；
- 不首行缩进；
- 段间距约 20–26px；
- 字色使用深灰而不是纯黑；
- 一段通常 2–4 句，约 80–180 个中文字符；
- 避免「一句话一个段落」的 AI 节奏。

### 5. 短段合并规则

排版阶段允许只改变换段，不改变文字：

- 连续普通文本段落如果单段明显过短，合并到 2–4 句；
- 目标段长约 80–180 中文字符；
- 最多合并 4 个源段；
- 图片、图注、列表、标题、引用前后不跨界合并；
- 明显作为转折/收束的独立金句可保留；
- 引用、数据定义、问句如果本身承担节奏作用可保留独立。

### 6. 重点句 / 重点词

不使用彩底高亮，不用左边蓝线。

默认用中文直角引号强调：

`「重点」`

规则：

- Markdown 的 standalone blockquote 变成独立重点句；
- 重点句 17px、600–700；
- 无背景、无边框；
- 自动补「」；
- 行内 strong 可以转换为「」或保留轻度加粗，但避免满篇粗体。

### 7. 图片

- width: 100%；
- 不加卡片、阴影、厚圆角；
- 图片上方留白约 30px；
- 图片后紧接图注；
- 竖图也不强制拉满失真。

### 8. 图注

《人物》图注在图片右下方，是弱信息。

默认：

- 12px；
- #8a8a8a / #999；
- **右对齐**；
- 行高约 1.5；
- 与图片间距 4–8px；
- 与后文间距约 28–34px；
- 不居中；
- 不斜体。

### 9. 参考资料：滚动框

文章最后的参考资料默认放进一个固定高度可滚动框，而不是把十几条引用铺满正文。

建议：

- 标题：`参考资料：`；
- 外框：1px 浅蓝或中性灰细线；
- padding 12–16px；
- max-height / height 约 260–340px；
- overflow-y: auto；
- -webkit-overflow-scrolling: touch；
- 字号 12.5–13px；
- 行高约 1.7；
- 文字使用 #888；
- URL word-break: break-all。

兼容策略：即使微信把 overflow 过滤掉，引用区只会展开，不应造成信息丢失。

### 10. 结尾

默认**不要**生成：

- 星标提醒；
- 点赞 / 在看 / 转发；
- 关注公众号；
- 往期推荐；
- 尾部营销海报。

文章停在内容自己的结论或参考资料即可。

## 三、微信复制兼容规则

微信编辑器会过滤 class、style 标签和部分高级 CSS，因此复制区域必须：

- 关键样式全部 inline；
- 不依赖 class；
- 不依赖外部 CSS；
- 不使用 CSS variables；
- 正文不使用 Grid/Flex 做关键布局；
- 不用 absolute positioning；
- 不用伪元素生成关键文字；
- 复杂结构优先做成图片；
- 图片使用 HTTPS；
- 标题字段与正文分离。

复制按钮应同时写入剪贴板：

- `text/html`：带内联样式的富文本；
- `text/plain`：纯文本 fallback。

不要让用户手动框选作为主复制路径；按钮复制更稳定。

---

## 四、图片策略

最稳定的路径：

1. 图片已在公开 GitHub / CDN；
2. renderer 将 `./assets/foo.jpg` 转成公开 HTTPS；
3. 预览页和复制内容都引用 HTTPS；
4. 粘到公众号后检查图片是否被微信转存；
5. 若远程图未自动转存，正文格式仍保留，只手工补图片。

## 五、Agent 执行流程

### Step 1｜读完整稿件

确认：标题、正文、图片、图注、引用区、是否有 CTA。

### Step 2｜做结构清理

- 识别 lead；
- 识别章节标题；
- 合并碎段；
- 识别重点句；
- 识别图片 + 图注；
- 识别参考资料；
- 去掉明确宣传尾巴。

这一步只改变版式结构，不改变字句和逻辑。

### Step 3｜转 HTML + 全内联

复制区只保留简单标签：p / section / h2 / h3 / strong / img / ol / ul / li / a。

### Step 4｜预览页

页面外壳可有 CSS/JS，但复制区必须独立。

提供：

- 复制正文（富文本）；
- 手动选中 fallback；
- 标题提示；
- 图片数量检查状态。

### Step 5｜微信实机验收

排版不能只看浏览器。

至少做：

1. 微信后台粘贴；
2. 保存预览；
3. 手机端看 1 次；
4. 检查滚动引用框；
5. 检查图片图注；
6. 检查段落是否过碎或过密。

---

## 六、验收标准

- 第一屏有清晰的引言层；
- 正文没有大量一句话一段；
- 小标题都是克制的「标题」形式；
- 重点不是彩色高亮，而是「」和适度粗体；
- 图注右对齐、小字、浅灰；
- 参考资料在可滚动细边框容器里；
- 无星标/关注/点赞尾巴；
- 复制区不存在 class 依赖；
- 所有正文图片为 HTTPS；
- 手机上看起来像编辑部文章，不像 Markdown 主题。

## 七、Codex 实现要求

通用 CLI：

`python render.py --input article.md --output article_wechat.html --asset-base https://...`

renderer 至少要实现：

- frontmatter；
- optional author/editor；
- lead；
- 短段自动合并；
- 「」标题；
- 「」重点句；
- 右对齐图注；
- 参考资料滚动框；
- 去宣传尾巴；
- HTTPS 图片重写；
- Clipboard API 富文本复制；
- Playwright 截图回归。
