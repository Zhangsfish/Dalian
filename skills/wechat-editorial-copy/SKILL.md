# wechat-editorial-copy

## 目标

输入一篇已经完成内容审核的 Markdown 稿件，输出一个浏览器可打开的 HTML 预览页。

用户只需要：

1. 打开 HTML；
2. 点击「复制正文（富文本）」；
3. 在微信公众号后台新建图文；
4. 单独填写标题；
5. 在正文区粘贴；
6. 检查图片和段落后保存。

**不尝试自动 push 草稿箱。**

## 核心边界

### 本 skill 做

- Markdown → HTML
- 把正文样式全部写成 inline style
- 生成可视化预览页
- 生成「复制正文（富文本）」按钮
- 检查图片数量和路径
- 图片改写成可公开访问的 HTTPS URL
- 为正文、标题、引用、图片、图注、来源建立统一排版

### 本 skill 不做

- 不改写正文核心观点
- 不为了“适合公众号”擅自删内容
- 不改数据
- 不增加没有证据的事实
- 不调用公众号 API
- 不自动发布

## 默认视觉方向：人物式克制长文

这里不是机械复刻某个公众号 CSS，而是抽取用户提供截图里的稳定特征：

- 长文允许很长，但视觉上切成很多短段；
- 图片承担主要视觉呼吸点；
- 黑白灰为主，不靠品牌色；
- 标题不用蓝色/橙色色块；
- 强调优先用字号、粗细、留白、细线；
- 图注很轻，不与正文竞争；
- 文章看起来像编辑部排出来的文章，而不是 Markdown 主题渲染器。

### 正文

- 16px
- 行高 1.9–2.0
- 段落下边距约 1.1em
- 不首行缩进
- 可 text-align: justify
- 尽量不写死正文颜色，兼容微信亮/暗模式

### 二级标题

- 22px 左右
- 700 粗体
- 上方留白约 3em
- 不使用彩色背景框
- 不使用 emoji
- 不加 PPT 式装饰

### 三级标题

- 18px 左右
- 700 粗体
- 与正文自然衔接

### 引用 / 金句

- 17px 左右
- 600–700 粗体
- 可以只有 2px 灰色左线
- 不用大面积灰底或彩底

### 图片

- 正文宽度 100%
- 横图优先
- 图前留白约 2em
- 图注 12px、灰色、居中
- 不套卡片，不加阴影

## 微信复制兼容规则

微信公众号编辑器会过滤部分 CSS，因此复制区域必须遵守：

- 全部关键样式写 inline style；
- 不依赖 class；
- 不依赖外部 CSS；
- 不使用 CSS variables；
- 不用 grid / flex 组织正文；
- 不用绝对定位；
- 不用伪元素生成关键文字；
- 复杂双栏关系直接做成图片；
- 标题字段与正文分离，复制区内不重复文章大标题。

预览页外壳可以使用 class 和 JS，但复制区域必须独立可用。

## 图片策略

最可靠方案：

1. 图片先放到公开 GitHub 仓库；
2. Markdown 相对路径转换为 raw.githubusercontent.com HTTPS 地址；
3. 预览和复制都使用 HTTPS 图片。

如果只有本地图片，可以生成预览，但必须提示用户：粘贴后图片可能需要手动补插。

## Agent 执行流程

### Step 1｜读取完整稿件

确认正文、标题、图片、图注、来源区都完整。不要从片段推测。

### Step 2｜排版审计

只判断结构层级，不改内容逻辑：正文 / 章节标题 / 引用 / 图片 / 图注 / 来源。

### Step 3｜渲染

Markdown 转 HTML，然后逐标签写 inline style。

来源区自动降级：

- 12–13px
- 灰色
- 行高约 1.7
- 不抢正文注意力

### Step 4｜生成预览页

预览页必须有：

- 标题预览（复制区外）
- 「复制正文（富文本）」按钮
- 「手动选中正文」备用按钮
- 成功/失败状态提示

复制优先使用 Clipboard API，同时写入 text/html 与 text/plain；不支持时 fallback 到 Range + execCommand('copy')。

### Step 5｜验收

必须检查：

- 图片数量是否与稿件一致；
- p / h2 / h3 / blockquote / img / li 是否都有 inline style；
- 图片是否全部为 HTTPS；
- 复制区是否重复文章大标题；
- 是否残留 wenyan/lapis 彩色主题风格；
- 是否存在大色块、渐变、胶囊标签、PPT 风卡片。

## 默认输出

`<文章名>_微信复制版.html`

用户最终操作只应该是：

> 打开 HTML → 点复制 → 粘贴到公众号
